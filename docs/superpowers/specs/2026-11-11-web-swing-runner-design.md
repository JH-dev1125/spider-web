# 웹스윙 러너 — 설계 문서

작성일: 2026-11-11 · 상태: 사용자 승인 대기 → 승인됨(2026-11-11, "딱히 없어")

## 1. 의도

친구들과 점수를 겨루는 가벼운 브라우저 게임. 스파이더맨에서 영감을 받은 캐릭터가 끝없는 도시를 웹스윙으로 가로지른다. 핵심 재미는 세 가지다.

1. **고르는 맛**: 건물이 듬성듬성 있어서 어느 건물에, 얼마나 멀리 거미줄을 쏠지 판단해야 한다.
2. **속도감**: 천천히 빨라지면서 도시가 스쳐 지나간다.
3. **몸으로 하는 조작**: 웹캠 앞에서 손으로 스파이더맨 동작을 하면 거미줄이 나간다.

"한 판만 더"의 동력은 **최고 점수 갱신**이다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 링크 하나로 설치 없이 실행 (GitHub Pages).
- 저사양 노트북에서 60fps 근처. 첫 로딩 용량 작게 (손 인식 모델 제외 자체 코드·에셋 < 1MB).
- 바이브코딩으로 계속 고치기 쉬운 구조: 빌드 도구 없음, 파일별 책임이 분명함.
- 키보드만으로도 완전히 플레이 가능.

**비목표 (지금은 안 함)**
- 실시간 멀티플레이, 상점, 캐릭터 성장, 아이템, 사운드(추후).
- 모바일 터치 조작.
- 손으로 그린 캐릭터 이미지 (교체 가능하게만 해둠).

**반목표 (이렇게 되면 실패)**
- 조작이 굼떠서 실수가 내 탓이 아니라고 느껴짐 (입력 지연·인식 오류로 죽음).
- 화면이 밋밋해서 속도감이 없음.
- 코드가 한 파일에 뭉쳐 수정할 때마다 다른 데가 깨짐.

## 3. 제약 (사용자 결정)

- 2D/2.5D, 고사양 아님, 용량 작게, 언어 가벼움.
- GitHub로 배포, 친구 대상.
- 시점: **등 뒤 시점 2.5D** (시안 A). 캐릭터는 화면 중앙에 있고 화면 안쪽(앞)으로 계속 전진. 건물은 좌우 양옆에서 다가온다.
- 사이드 건물은 **뜸하게** 배치 — 빈 구간이 있어 잘 골라야 한다.
- 웹슈팅 방향 **6개**: 왼쪽 상·중·하, 오른쪽 상·중·하.
- **누르는 시간(손동작 유지 시간)이 길수록 거미줄이 멀리** 나간다.
- 거미줄이 건물에 걸리면 스윙. **스윙이 끝날 즈음 거미줄이 자동으로 끊어지고** 새로 걸어야 한다.
- 거미줄이 없는 상태가 지속돼 **바닥에 닿으면 사망**. 한 판 = 사망까지.
- 점수 = 거리. 속도는 천천히 증가.
- 비주얼: 광활한 도시(겹겹의 원경 실루엣, 까마득한 바닥, 넓은 하늘). 캐릭터가 스윙·활강 중 구르기·무릎 굽히기 등 동작을 **랜덤**으로 하며 힙한 느낌.
- 웹캠 손동작 인식으로 조작.

## 4. 결정된 방식 (기획자 판단 — 사용자에게 고지함)

- **플랫폼**: 순수 HTML + JavaScript(ES 모듈) + Canvas 2D. 게임 엔진·번들러·npm 없음. 로컬 실행은 정적 서버 하나(`python -m http.server`)면 됨.
- **손 인식**: Google MediaPipe Hand Landmarker (CDN 로드, 브라우저 내 처리, 영상 외부 전송 없음). 웹캠 미허용/미지원 시 자동으로 키보드 모드.
- **키보드 기본 배치**: 왼쪽 상·중·하 = `Q`·`A`·`Z`, 오른쪽 상·중·하 = `E`·`D`·`C`. 누르고 있으면 거미줄 길이가 늘고, 떼는 순간 발사.
- **그래픽**: 건물·도시·캐릭터 모두 코드로 그림(이미지 파일 0). 캐릭터 그리기는 한 파일에 격리해 나중에 스프라이트로 교체 가능.
- **최고 점수**: `localStorage`.
- **멀티(추후)**: 첫 단계는 친구 점수 순위표. 지금은 점수 저장을 한 곳(함수 하나)으로 모아두는 것까지만.
- **저작권**: 캐릭터 이름·코스튬은 오리지널(빨강/검정 계열의 가면 쓴 거미 영웅, 이름은 가칭 "웹러너"). 공개 저장소 안전.

## 5. 게임 동작 상세

### 5.1 공간과 카메라
- 월드 좌표: x = 좌우, y = 높이(위가 +), z = 전진 방향.
- 원근 투영 카메라가 캐릭터 뒤 위쪽에서 따라감. 화면 중앙 근처에 캐릭터.
- 길(가운데 통로)의 양옆 x = ±W 위치에 건물이 z를 따라 생성된다. 건물마다 z 길이·높이·간격이 랜덤. **간격(빈 구간)은 진행할수록 넓어진다.**
- 건물은 캐릭터 뒤로 지나가면 제거, 앞쪽 시야 끝에서 새로 생성(무한).

### 5.2 웹슈팅
- 6방향 = {왼, 오} × {상, 중, 하}. 각 방향은 캐릭터 기준 고정 각도의 광선(앞쪽으로 약간 기울어 전방 건물을 노림). 상/중/하는 광선의 높이 각도.
- 충전: 입력을 누르고 있는 동안 길이가 최소→최대로 증가(약 1초에 최대). 화면에 조준선 미리보기(점선, 현재 길이)를 그린다.
- 발사: 입력을 떼면 광선이 현재 길이까지 진행. 그 안에서 건물 측면에 처음 닿는 지점이 앵커. 없으면 빗나감(짧은 거미줄 연출 후 사라짐).
- 거미줄은 한 번에 하나. 새로 걸면 이전 것 해제.

### 5.3 스윙 물리
- 앵커가 있으면 진자 운동: 캐릭터와 앵커 사이 거리를 최대 길이로 하는 로프 제약 + 중력. 전진 속도는 유지되며 스윙으로 가속 가능.
- **자동 해제**: 스윙이 최저점을 지나 앵커 쪽으로 다시 올라가기 시작한 뒤(또는 앵커가 캐릭터 뒤로 일정 각도 이상 넘어가면) 거미줄 자동 해제 → 관성으로 활강.
- 활강 중엔 중력으로 하강. 높이 0(바닥) 도달 = 사망.
- 기본 전진 속도는 시간에 따라 천천히 증가(상한 있음).

### 5.4 점수와 난이도
- 점수 = 전진 거리(미터 표기). 화면 상단에 현재/최고 점수.
- 난이도 곡선: 시간·거리에 따라 기본 속도↑, 건물 간격↑, 건물 높이 편차↑. 초반 20초는 쉽게.

### 5.5 연출
- 원경: 하늘 그라데이션, 2~3겹 도시 실루엣 패럴랙스, 저 아래 바닥(거리 불빛).
- 속도감: 속도에 비례하는 화면 가장자리 속도선, 시야각(FOV) 확대, 스윙 최저점 가벼운 화면 흔들림.
- 캐릭터 포즈: 스윙(팔 뻗음), 활강(대자), 구르기(회전), 무릎 굽히기(웅크림) 등. 거미줄 해제 직후·활강 중 랜덤으로 트릭 포즈 선택해 짧게 재생.
- 사망: 낙하 연출 → 결과 화면(점수, 최고 점수, 다시하기: `Space`/`Enter` 또는 손 펴기).

### 5.6 화면 흐름
타이틀(조작 선택: 웹캠/키보드, 조작법 안내) → 플레이 → 결과 → 플레이.

## 6. 손동작 인식 (시험판으로 먼저 검증)

- 손 모양: 스파이더맨 "웹 슈팅" 제스처(검지·새끼 펴고 중지·약지 접음)를 **발사 준비/충전** 신호로 본다.
- 좌/우: 어느 손(MediaPipe handedness, 거울 보정)인지 또는 화면상 손 위치의 좌우 절반.
- 상/중/하: 손목의 화면 내 세로 위치를 3등분.
- 길이: 제스처를 유지한 시간 = 충전. 제스처가 풀리면 발사.
- 떨림 방지: 제스처 판정은 연속 N프레임 일치 시 확정.
- **시험판(spike)**: 본 게임 전에 웹캠 + 제스처 판정 + 6방향/충전 표시만 하는 버리는 페이지를 만들어 조작감 확인. 결과에 따라 6절 규칙을 수정. 판정이 불안정하면 "좌/우 = 화면 절반, 상/중/하 = 높이"만 쓰고 손 모양은 '주먹 쥐기=충전'처럼 단순화하는 대안을 쓴다.

## 7. 코드 구조

```
index.html          진입점, canvas, 스크립트 로드
src/main.js         게임 루프, 화면 상태(타이틀/플레이/결과)
src/config.js       모든 수치(속도, 중력, 간격, 키 배치) 한 곳
src/world.js        건물 생성·제거, 난이도 곡선
src/player.js       캐릭터 상태, 스윙 물리, 사망 판정
src/web.js          6방향 조준, 충전, 광선-건물 충돌
src/input.js        입력 추상화: 키보드/손 → {side, level, charging, released}
src/hand.js         MediaPipe 손 인식 → input.js 이벤트
src/render.js       카메라 투영, 배경·건물·거미줄·속도선
src/character.js    캐릭터 포즈 그리기(교체 지점)
src/score.js        점수, 최고 점수 저장 (추후 순위표 연결 지점)
tests/              브라우저에서 여는 단순 assert 테스트 페이지(물리·충돌·난이도)
```

원칙: 게임 로직(world/player/web)은 그리기·입력을 모른다 → 테스트 가능. 수치는 전부 `config.js`.

## 8. 배포

- GitHub 저장소 루트를 GitHub Pages로 서빙. 빌드 없음. 웹캠은 HTTPS 필요 → Pages는 HTTPS라 문제없음. 로컬은 `localhost`라 허용.
- `README.md`에 실행·배포 방법.

## 8.5 검토 후 기획자 결정 (사용자가 기획을 위임함 — 확인 시 뒤집을 수 있음)

1. **좌우 이동**: 3D 진자. 왼쪽에 걸면 왼쪽으로 끌려가며 x가 자유롭게 움직인다. 카메라는 x를 부드럽게 따라가 캐릭터가 화면 중앙 근처에 머문다. 통로 벽(건물 면)에 닿으면 사망이 아니라 **튕겨 나오며 속도 일부 손실**. 건물이 없는 구간의 x는 ±W로 제한.
2. **고도 회복 (루프 A)**: 스윙을 잘 타면 고도가 오른다. 걸리는 순간 로프를 현재 거리의 ~85%로 **살짝 감아올리고**, 자동 해제 시 속도 방향 그대로 날아가며 **해제 부스트**(상향+전진 소량)를 준다. 별도 "가속" 입력은 없음 — 타이밍(어느 건물·길이 선택)이 실력.
3. **높이 관계**: 시작 고도는 건물 높이 중간쯤. 건물 높이 분포는 캐릭터 고도보다 대체로 높게 → 상(앞위)·중(앞옆)·하(앞아래) 모두 쓸모. 캐릭터가 건물보다 높으면 '상'은 빗나갈 수 있음(의도된 판단 요소). 높이 상한(하늘 천장)은 두어 무한 상승 방지.
4. **손 모드 방향 확정**: 방향(좌우·상중하)은 **떼는 순간의 최근 안정 위치**로 확정, 충전 중 조준선은 실시간 갱신. 손 트래킹이 300ms 이상 끊기면 **취소**(발사 안 함).
5. **시험판 순서**: 키보드 본 게임과 **병행**. 조작감 판정은 사용자. 대안 제스처도 불안정하면 키보드만으로 1차 배포.

## 9. 빌더에게 맡기는 것

- 정확한 물리 상수, 카메라 위치, 건물 크기·색, 포즈 디자인, 속도선 모양.
- 난이도 곡선의 구체 수식 (단, 초반 20초 쉬움 + 점진 증가).
- 테스트 범위 (물리·충돌·생성의 핵심 로직은 반드시).
